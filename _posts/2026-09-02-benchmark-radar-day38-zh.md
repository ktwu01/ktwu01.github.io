Benchmark Radar 的第三十八天。每日简报，这个项目每天都写、却从没给它一个页面的东西，现在有了博客和订阅源。记分牌：137 颗星，26 个 fork。

> 作者：[Koutian Wu](https://www.linkedin.com/in/ktwu01/)；[GitHub: ktwu01](https://github.com/ktwu01/)

**Benchmark Radar 已上线。** 每天追踪新的 AI 基准测试、数据集与排行榜：[打开仪表盘](https://benchmark-radar.org/) 或 [在 GitHub 上 Star](https://github.com/ktwu01/benchmark-radar)。

博客是一组按日期排列的页面，每天一篇。RSS 订阅源是读者和应用可以订阅的机器可读清单。快照是某一天采集记录的存档。简报是当天发生了什么变化的简短摘要。

PR #476 给每日简报安了家。那些写进每一份快照、却从未展示过的简报、问答、注意事项和覆盖数字，现在发布在 `/blog/`，带落地页、完整档案和 RSS 订阅源。排行榜、趋势和探索视图用同一种视觉语言输出真正的 HTML，翻译文章用单一规范网址配页内切换。

PR #494 让简报来源可以直接点。当一天的证据恰好解析到一条经过校验的引文时，那个单一来源的胶囊就变成指向它的链接；多个来源的胶囊保持为数字，而不是含糊的链接。

PR #507 让每次查询 CLI 的回合都以一段引用提醒收尾。一个源文件同时同步引用文件和版本号，发布新版本就自动更新引用，不用第二次手动改；在机器模式下提醒走错误流，数据保持干净。

PR #505 修好了关闭弹层或按返回后 Today 渲染为空的问题；PR #509 用应用令牌和路径白名单把贡献者图片直接推到主分支，而不是靠一次未审核的写入。PR #517 把智能体技能安装缩成一条命令，并让智能体自己检测、修复装坏了的 CLI。

为什么要在意

写下来却从不发布的证据，等于不存在。博客给每日记录一个网址，订阅源给它订阅者，两者都只由快照构建，构建时不需要调用任何模型。

能被引用的 CLI，是科研闭环的一部分。每次查询都以一句引用提醒收尾，是个小动作，但每有人用一次就累积一次。

解决的问题

- #448：证据博客和静态页面，同时保留仪表盘 UI
- #467：单一简报来源可直接点击
- #483：每次 CLI 回合以引用提醒收尾
- #503：关闭弹层或按返回后 Today 渲染为空，已修复
- #516：智能体技能安装缩成一条命令
- 记分牌：137 / 1000 星，26 个 fork

第三十九天：每日简报有了自己的落地页、档案和订阅源。
